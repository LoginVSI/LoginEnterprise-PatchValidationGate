# Architecture

The loop is manifest, adapter apply/verify, existing application test, collection, deterministic verdict, evidence, approval, simulated promotion, existing continuous test, and issue closure.

One function lives in each module file. Appliance HTTP uses Invoke-LEGateRequest; GitHub uses a separate fixed-origin helper with normal TLS. Only GET is retried. Logging, UTC conversion and reason codes are centralized.

Collection preserves private responses, pages, relationships and screenshot bytes before normalization. A small spec-derived response profile isolates selectors and envelopes; private capture confirmation remains required for live evaluation. The evaluator consumes normalized data. Export hashes stored bytes. Publication creates a separate allowlisted projection without changing the decision.

A durable target lease plus exclusive file lock serializes cooperating operators. Identity binds change ID, test, target, exact policy/manifest/profile bytes, adapter and promotion mode. Resume requires this identity and a recorded run ID. A matching name alone never permits reuse. Timeout retains the lease until completion and explicit restoration. Every runner/operator must use the same state location.

Jobs transfer the immutable sanitized artifact and independently pass its manifest hash. Later handoff artifacts remain separate. Manual approval requires reviewer/time provenance; auto mode enforces supported functional guards. No production deployment system is called.

See [recovery](runbook.md), [API assumptions](api-assumptions.md), and [security](security.md). Local lab validation and restoration are verified as recorded in the [walkthrough](tested-lab-walkthrough.md); Actions acceptance remains pending.

Change detection and invocation belong to the caller. No scanner or resident lifecycle controller is supplied. Native LE Events remain evidence; deterministic code assigns gate verdicts. GitHub issues are optional reporting records. A real deployment integration must confirm its own outcome before continuous handoff. The reference only simulates production promotion and confirms enabled continuous scheduling on readback.
